# STM32H723VGT6 + Waveshare 3.5" TFT Touch Shield (без графического фреймворка)

## 1. Обзор проекта

Проект (с нуля): подключить Waveshare 3.5" TFT Touch Shield (ILI9486, 480x320, резистивный тач
XPT2046) к плате **WeAct Studio Mini STM32H723VGT6** по SPI, чистым HAL/регистрами, без TouchGFX/LVGL.
https://www.waveshare.com/wiki/3.5inch_TFT_Touch_Shield

Среда: STM32CubeMX (отдельное приложение) + STM32CubeIDE 2.2.0. С 2026-09-22 в проект добавлена
параллельная ветка на Arduino IDE + `stm32duino` core (см. §8).

**Статус на старте:**
- Питание проверено: экран подключён, светится ровным белым по всей площади через шлейф →
  подсветка и питание модуля исправны (см. `my_project1.jpg`).
- Контакты уже распаяны согласно таблице пинов ниже (см. `ESP-GPIO.jpg`).
- Ардуино-референс проверен и работает "из коробки": `Arduino\LCD_Show` и `Arduino\LCD_Touch`
  из официального пакета Waveshare (`3.5inch_TFT_Touch_Shield_Code_V2\...\Arduino\`).

## 2. Железо

### 2.1 Плата WeAct Studio Mini STM32H723VGT6

- Cortex-M7, LQFP100, 82 физических GPIO
- Кварц HSE 25 МГц, кварц LSE 32.768 кГц
- Занятая периферия на плате (НЕ трогать при выборе пинов):

| Периферия | Пины |
|---|---|
| SPI-флешка (W25Q64, обычная) | PB3(CLK), PB4(MISO), PD6(CS), PD7(MOSI) |
| QSPI-флешка (вторая, W25Q64) | PB2(CLK), PB6(NCS), PD11(IO0), PD12(IO1), PE2(IO2), PD13(IO3) |
| MicroSD (SDMMC1) | PC8,PC9,PC10,PC11,PC12,PD2,PD4 |
| Камера (DCMI + I2C1) | PA4,PA6,PA7,PA8,PB7,PC6,PC7,PD3,PE0,PE1,PE4,PE5,PE6,PB8,PB9 |
| Кварцы | PH0,PH1 (HSE 25МГц), PC14,PC15 (LSE) |
| USB | PA11(DN),PA12(DP) |
| SWD | PA13(SWDIO),PA14(SWCLK) |
| Встроенный TFT ST7735 (SPI4, 160x80) | PE10(BL),PE11(CS),PE12(SCK),PE13(DC),PE14(MOSI) |
| Синий LED | PE3 |
| Кнопка K1 | PC13 |

Источник: разбор схемы платы, сверено с официальным рендером платы `STM32H7xx_2.jpg` (там же видно,
что PB13/PB14/PB15 физически выведены на гребёнку).

Выбранные ниже пины (SPI2 + PC0-PC5) **не пересекаются** с встроенным дисплеем (SPI4) — можно будет
позже одновременно использовать оба экрана.

### 2.2 Waveshare 3.5" TFT Touch Shield — какие сигналы нужны

9 сигналов (без SD-карты и TP_BUSY — они не критичны для старта):
SCLK, MISO (для тача), MOSI, LCD_CS, LCD_DC, LCD_RST, LCD_BL, TP_CS, TP_IRQ.

### 2.3 Итоговая таблица пинов (SPI2)

| Waveshare (экран) | STM32 пин | Назначение | Режим в CubeMX |
|---|---|---|---|
| 5V | 5V платы | питание модуля | - |
| GND | GND | земля | - |
| SCLK | **PB13** | SPI2_SCK | Alternate Function (через выбор SPI2) |
| MISO | **PB14** | SPI2_MISO (нужен для тача) | Alternate Function |
| MOSI | **PB15** | SPI2_MOSI | Alternate Function |
| LCD_CS | **PC0** | выбор чипа экрана | GPIO_Output |
| LCD_DC | **PC1** | команда(0)/данные(1) | GPIO_Output |
| LCD_RST | **PC2** | аппаратный сброс экрана | GPIO_Output |
| LCD_BL | **PC3** | подсветка | GPIO_Output |
| TP_CS | **PC4** | выбор чипа тача | GPIO_Output |
| TP_IRQ | **PC5** | прерывание тача | GPIO_Input |

Не используем пока: SD_CS, SD_CD, TP_BUSY (можно подключить позже при необходимости). Все пины
проверены как свободные (нет пересечения с таблицей "занятая периферия" выше).

**Аппаратная особенность шилда** (подробный разбор и первичные источники — в `PRIZMA-DOSTOVERNOSTI.md`
§4.1): "SPI"-сигналы (SCLK/MOSI/CS/DC) на самом деле поступают на пару сдвиговых регистров `74HC4094`
+ `74HC04` (буфер) + `74HC4040` (счётчик) на обратной стороне шилда, которые эмулируют параллельную
8080-16 шину для настоящей матрицы ILI9486. RST и BL идут на панель напрямую, в обход регистров.
Практическое следствие: MISO физически подключён только к тач-контроллеру XPT2046, никогда к
ILI9486 — обратного пути с панели нет и не может быть.

<details>
<summary>Подробная инструкция по шагам (на случай, если нужно повторить с нуля)</summary>

1. **Создание проекта** — `File → New Project` → MCU Selector → `STM32H723VGT6` (LQFP100) →
   Start Project.
2. **System Core → RCC** — HSE: Crystal/Ceramic Resonator. LSE, если нужен RTC в будущем — можно
   пропустить сейчас.
3. **Trace and Debug → DEBUG** (в этой версии CubeMX вынесен из SYS в отдельную категорию) — Mode:
   Serial Wire (оставляет SWDIO/SWCLK для отладчика).
4. **Connectivity → SPI2** — Mode: Full-Duplex Master (не Transmit Only — тачу XPT2046 нужен приём
   по MISO). Проверить, что подсветились именно PB13(SCK)/PB14(MISO)/PB15(MOSI) — у SPI2 на H723
   есть альтернативные наборы пинов. Если не те — кликнуть на пин на картинке чипа и выбрать нужную
   Alternate Function вручную. Data Size/Prescaler/CPOL/CPHA на этом шаге не трогать (донастроим
   позже; по умолчанию Data Size = 4 Bits — тоже поправить потом на 8 Bits).
5. **GPIO для LCD** — PC0/PC1/PC2/PC3 → `GPIO_Output`.
6. **GPIO для тача** — PC4 → `GPIO_Output` (CS тача), PC5 → `GPIO_Input` (IRQ, опрос вручную, без
   EXTI).
7. **User Label** (System Core → GPIO) — PC0=`LCD_CS`, PC1=`LCD_DC`, PC2=`LCD_RST`, PC3=`LCD_BL`,
   PC4=`TP_CS`, PC5=`TP_IRQ`. Важно: без суффикса `_Pin` — CubeMX добавит его сам.
8. **GPIO Mode/Speed** — PC0-PC4: Output Push-Pull, No pull, Low/Medium speed. PC5: Input, Pull-up
   (чтобы не плавал, если IRQ не подключён). Начальный уровень/полярность (LOW/HIGH активно) —
   уточняется экспериментально на этапе программирования.
9. **Проверка конфликтов** — убедиться, что PB13/14/15/PC0-5 не подсвечены как занятые (см. таблицу
   §2.1).
10. **Сохранить проект** — `File → Save Project as…` → `STM32-1-ANALYZE`. Generate Code — отдельным
    шагом, после подтверждения плана пинов.
11. Дальше: Clock Tree → Project Manager → Toolchain = STM32CubeIDE → Generate Code → Import в
    CubeIDE (`File → Import → General → Existing Projects into Workspace`) → донастройка SPI2 Data
    Size/Prescaler/CPOL/CPHA под ILI9486 → свой драйвер LCD_WriteCmd/LCD_WriteData (см. §5).

## 4. Структура сгенерированного кода

```
Core/Inc/main.h                 — объявления пинов, прототипы
Core/Inc/stm32h7xx_it.h         — прототипы обработчиков прерываний
Core/Inc/stm32h7xx_hal_conf.h   — какие модули HAL включены (SPI, GPIO, RCC...)
Core/Src/main.c                 — точка входа, конфигурация тактирования и периферии
Core/Src/stm32h7xx_hal_msp.c    — низкоуровневая настройка GPIO/тактирования ПОД периферию
Core/Src/stm32h7xx_it.c         — обработчики прерываний (исключения CPU + SysTick)
Core/Src/system_stm32h7xx.c     — самая ранняя инициализация чипа (до main())
Core/Src/syscalls.c, sysmem.c   — заглушки для printf/malloc (стандартная библиотека C)
Core/Startup/startup_...s       — ассемблер: таблица векторов, запуск CPU
Drivers/                        — библиотеки ST (HAL + CMSIS), не трогаем
STM32H723VGTX_FLASH.ld/_RAM.ld  — linker-скрипты (карта памяти)
STM32H723VGT6-Waveshare.ioc     — файл CubeMX, источник истины для всей этой генерации
```

Ключевой принцип: свой код — только между `/* USER CODE BEGIN ... */` и `/* USER CODE END ... */`.
Всё вне этих маркеров сгенерировано CubeMX и будет затёрто при повторной генерации из `.ioc`.

### `Core/Src/main.c` — порядок выполнения

`main()` (main.c:68-110):
1. `MPU_Config()` — Memory Protection Unit, запрет доступа к нулевому адресу (защита от NULL) —
   стандартная заготовка CubeMX
2. `HAL_Init()` — сбрасывает периферию, включает SysTick на 1мс тик
3. `SystemClock_Config()` — настоящая настройка тактирования (см. ниже)
4. `MX_GPIO_Init()` и `MX_SPI2_Init()` — включают наши пины и SPI2
5. `while(1) {}` — бесконечный цикл (сюда добавлен наш тест экрана, см. §5)

**`SystemClock_Config()` (main.c:116-169):**
- `HAL_PWREx_ConfigSupply` + `VOLTAGESCALING_CONFIG(SCALE1)` — питание ядра на максимум (нужно для
  400 МГц)
- `PLLSource = RCC_PLLSOURCE_HSE` — 25 МГц кварц
- `PLLM=2, PLLN=32, PLLP=1` — 25МГц/2=12.5МГц (вход VCO) × 32 = 400МГц (выход)
- `RCC_ClkInitStruct` — как 400 МГц раздаются по шинам (AHB/2=200, APB/2=100)
- `FLASH_LATENCY_2` — число тактов ожидания при чтении Flash на этой частоте

**`MX_SPI2_Init()` (main.c:175-216):**
- `Mode=MASTER`, `Direction=2LINES` — полный дуплекс (SCK+MOSI+MISO)
- `DataSize=8BIT`, `CLKPolarity=LOW`, `CLKPhase=1EDGE` — SPI Mode 0, байт за раз
- `NSS=SOFT` — аппаратный CS не используется, CS дёргаем вручную через обычный GPIO
- `BaudRatePrescaler=32` → 6.25 МБит/с
- Остальные поля (`NSSPMode`, `MasterSSIdleness`, `FifoThreshold`...) — новые для H7 параметры, не
  влияют на нас, т.к. NSS=SOFT

**`MX_GPIO_Init()` (main.c:223-264)** — важный нюанс:
```c
HAL_GPIO_WritePin(GPIOC, LCD_CS_Pin|LCD_DC_Pin|LCD_RST_Pin|LCD_BL_Pin|TP_CS_Pin, GPIO_PIN_RESET);
```
Выполняется до перевода пинов в режим выхода — задаёт исходное состояние. При старте все 5 выходов
LOW: LCD_CS=0 (экран выбран), LCD_DC=0 (режим команды), LCD_RST=0 (**экран в сбросе**), LCD_BL=0
(подсветка выключена — активна по HIGH, судя по официальному Arduino-драйверу). Нормальная отправная
точка — сброс держится, пока код явно его не отпустит.

Также видна `HAL_SYSCFG_AnalogSwitchConfig(...PC2/PC3...CLOSE)` — не ошибка, а особенность H723: у
PC2/PC3 есть доп. площадка (PC2_C/PC3_C), CubeMX сам корректно подключает её при использовании этих
пинов как GPIO.

### `Core/Src/stm32h7xx_hal_msp.c` — вторая половина конфигурации периферии

Не дублирование `main.c`. HAL использует паттерн "MSP" (MCU Support Package): `HAL_SPI_Init(&hspi2)`
сам внутри вызывает `HAL_SPI_MspInit(hspi)`, определённую здесь:
- включается тактирование SPI2 и его источник (`RCC_SPI123CLKSOURCE_PLL`)
- PB13/14/15 настраиваются как **Alternate Function** (`GPIO_MODE_AF_PP`, `GPIO_AF5_SPI2`), а не
  простой GPIO

Правило: обычные GPIO (LCD_CS и т.п.) — в `main.c → MX_GPIO_Init()`; пины периферии (шина SPI) — в
`stm32h7xx_hal_msp.c`. Так CubeMX генерирует всегда.

### Остальное (коротко)

- **`stm32h7xx_it.c`** — обработчики исключений CPU (просто бесконечный цикл при HardFault и т.п.);
  `SysTick_Handler` вызывает `HAL_IncTick()` — от этого зависят `HAL_Delay()`/`HAL_GetTick()`
- **`system_stm32h7xx.c`** — вызывается ещё до `main()`, включает FPU и минимальный бутстрап чипа
- **`syscalls.c`/`sysmem.c`** — заглушки, чтобы линковщик не ругался при появлении `printf`/`malloc`
- **`startup_stm32h723vgtx.s`** — таблица векторов + первый код: стек, копирование `.data`, зануление
  `.bss`, вызов `SystemInit()`, затем `main()`
- **`.ld` файлы** — карта памяти (Flash/RAM), стек 0x400 байт, куча 0x200 байт

## 5. Драйвер экрана (HAL-ветка, `STM32-1-ANALYZE`)

Протокол SPI и порядок регистров инициализации ILI9486 взяты из официального, уже проверенного
пользователем на Arduino драйвера `Arduino\LCD_Show\LCD_Driver.cpp` (`LCD_Init()` → `LCD_Clear()`).
Из чтения этого файла:
- команда (регистр) шлётся как ровно **1 байт**, CS дёргается вокруг каждой отдельной посылки
- параметр шлётся как **2 байта**: `LCD_WriteData(uint16_t Data)` шлёт `Data>>8` затем `Data&0xFF` —
  для обычного 8-битного параметра типа `0x19` это будет `0x00, 0x19` (не ошибка — оригинальный
  протокол именно такой, см. `PRIZMA-DOSTOVERNOSTI.md` §5)
- сброс: RST→HIGH, 500мс, RST→LOW, 500мс, RST→HIGH, 500мс
- после списка регистров производителя (gamma/питание матрицы — заводская подстройка Waveshare)
  идёт: `0x3A=0x55` (формат пикселя 16 бит RGB565), `0x36=0x28` (ориентация D2U_L2R), `0x11` (Sleep
  Out) + пауза 120мс, `0x29` (Display On)
- заливка: `0x2A`/`0x2B` (окно X/Y) → `0x2C` (начать запись в GRAM) → нужное число пикселей по
  2 байта (RGB565), CS не отпускается между пикселями одной заливки

**`Core/Inc/lcd_ili9486.h`** — публичный интерфейс: `LCD_Init()`, `LCD_FillScreen(color)`, размеры
экрана (480×320), готовые цвета RGB565.

**`Core/Src/lcd_ili9486.c`** — реализация:
- `LCD_CS_Low/High` — обёртки над `HAL_GPIO_WritePin` для LCD_CS
- `LCD_WriteReg(reg)` — DC=0 (команда), CS=0, 1 байт по SPI, CS=1
- `LCD_WriteData8(data)` — DC=1 (данные), CS=0, 2 байта (`0x00`, значение)
- `LCD_Reset()` — аппаратный сброс, 500/500/500 мс
- `LCD_InitRegisters()` — список регистров производителя, построчно как в оригинале (сразу с
  финальными значениями `0xB6`/`0x36`, без промежуточной перезаписи — результат идентичен)
- `LCD_Init()` — включает подсветку (`LCD_BL` → HIGH), сброс, регистры инициализации, Sleep Out,
  Display On
- `LCD_SetWindow(xs,ys,xe,ye)` — прямоугольная область для следующей записи в GRAM
- `LCD_FillScreen(color)` — строит одну строку буфера (480×2=960 байт) один раз, затем 320 раз шлёт
  её по SPI без отпускания CS — сейчас через один `HAL_SPI_Transmit()` на всю строку (960 байт);
  побайтовый вариант, ближе к обоим официальным референсам, был протестирован отдельно и не изменил
  результат — статус и детали в `PRIZMA-DOSTOVERNOSTI.md` §5

## 6. Процедуры (как повторить измерения/прошивку)

### 6.1 Прошивка через DFU

См. `instruction-upload.jpg` в этой папке:
1. Зажать **BOOT0**, тапнуть **RESET/NRST**, подождать ~0.5 сек, отпустить BOOT0 → плата в USB DFU
2. STM32CubeProgrammer → Interface USB → Refresh → Connect
3. Erasing & Programming → Browse → указать `.elf` или `.bin` из папки `Debug/`
4. Обязательно галочка **"Run after programming"**
5. Start Programming

### 6.2 Live debug через ST-Link (STM32CubeIDE 2.2.0)

SWD допаян (4 контакта: `3V3`, `GND`, `SWDIO`=PA13, `SWCLK`=PA14), ST-Link (клон) подключён.
`Run → Debug Configurations...` → двойной клик на **`STM32 C/C++ Application`** (это ST-Link-путь;
`GDB Hardware Debugging` — для других зондов типа J-Link) → CubeIDE сам подставляет Project и путь к
`.elf` из `Debug/` → Debugger уже настроен на ST-LINK GDB server → кнопка **Debug**. После первого
раза конфигурация запоминается — повторный клик по зелёному жуку пересобирает/перепрошивает без
повторного мастера (спросит "Terminate and Relaunch", если старая сессия ещё висит).

**Частые ошибки при первом использовании (уже случались в этом проекте, не повторять):**
- CubeIDE **сама** ставит временный брейкпоинт на входе в `main()` при каждом запуске Debug —
  программа всегда сначала стоит в начале `main.c` (до `MPU_Config()`), нужно **Resume (F8)**, чтобы
  пройти дальше.
- **Expressions** — статичный снимок, обновляется только пока программа **стоит** на брейкпоинте.
  **Live Expressions** — обновляется во время работы (SWD "на лету", без остановки ядра) — то, что
  нужно для наблюдения за переменными в реальном времени (например `tp_x`/`tp_y` при касании).
- В панели Live Expressions колонка **Value** может быть обрезана за правый край панели — раздвинуть
  колонки/прокрутить вправо, иначе кажется, что значение "не меняется", хотя оно просто не видно.

### 6.3 Осциллограф Siglent SDS802X HD — план проверки линий шилда

Щуп x1 (сигнал 3.3В), земля щупа — на GND платы. Прошивка должна крутить `LCD_FillScreen` в цикле
(иначе на статичном сигнале ловить нечего). На каждый пин: подключить щуп → **Auto Setup** → снять
показание → следующий пин.

| Пин | Ожидается (норма) | Если не так |
|---|---|---|
| SCLK | короткие пачки прямоугольных импульсов (~6.25 МГц внутри пачки), повторяются циклично | ровная линия на 0В → сигнал не доходит физически (обрыв/пайка) |
| MOSI | то же самое — пачки импульсов | ровная линия → обрыв |
| LCD_CS | в основном 3.3В (высокий), коротко проваливается в 0В на время каждой передачи | всегда 0В или всегда 3.3В → CS не переключается |
| LCD_RST | один раз поднимается в 3.3В и остаётся там (после сброса) | застрял на 0В → экран физически в сбросе |
| LCD_BL | ровные 3.3В постоянно | 0В → подсветка не запитана |
| LCD_DC | дёргается между 0В и 3.3В (команда/данные) | ровная линия → DC не переключается |

**Результат замера (2026-09-13, все линии калиброванным щупом):**

| Пин | Результат | Вывод |
|---|---|---|
| SCLK | пачки импульсов, ~6.25МГц внутри пачки, амплитуда ~3.3В | норма |
| MOSI | полноразмерные переходы 0↔3.3В (3.317В) | норма |
| LCD_CS | в основном высокий, проваливается в 0В на время каждой заливки (~0.3-0.4с) | норма |
| LCD_RST | ровные ~3.24В, без провалов | норма |
| LCD_BL | ровные ~3.24В постоянно | норма |
| LCD_DC | резкие чистые переходы 0↔3.3В (триггер Single, 3.31В) | норма |

Интерпретация этого результата и его ограничения (щуп проверяет сигнал только на выходе STM32, не
после сдвиговых регистров) — в `PRIZMA-DOSTOVERNOSTI.md` §6.2. **Следующий, ещё не выполненный шаг
с этим прибором:** режим **Decode (SPI)** — до сих пор смотрели только уровни/наличие импульсов, не
сам байтовый контент MOSI.

## 7. Тач: чтение координат (диагностика, не финальный драйвер)

`Core/Src/lcd_ili9486.c` также содержит:
- `LCD_ReadID(uint8_t id[3])` — читает ID4-регистр ILI9486 (`0xD3`) через `HAL_SPI_TransmitReceive`:
  1 байт команды (DC=0), затем 4 байта чтения (DC=1, CS не отпускается между ними) — `rx[0]` дамми,
  `id[0..2] = rx[1..3]`. Ожидаемый по даташиту (8.2.76) ответ — `0x94 0x86`. **Результат на этой
  плате: `FF FF FF`** (объяснение — `PRIZMA-DOSTOVERNOSTI.md` §4.2, это ожидаемо, не баг).
- `TP_ReadRaw(uint16_t *x, uint16_t *y)` — читает X/Y с XPT2046 (control bytes `0xD0`/`0x90`) на той
  же физической линии MISO (PB14), но через `TP_CS` (PC4). Диагностическая, не финальный драйвер
  тача — у XPT2046 чтение по SPI штатное и многократно проверенное (в отличие от эксперимента с
  ILI9486), поэтому по её показаниям можно судить о приёме по MISO вообще. Статус теста и открытые
  версии — `PRIZMA-DOSTOVERNOSTI.md` §6.3.

В `main.c`: `volatile uint8_t lcd_id[3]` и `volatile uint16_t tp_x, tp_y` — глобальные, видны в
Expressions/Live Expressions без доп. Watch-выражений.

## 8. Ветка Arduino IDE + stm32duino (`STM32-ARDUINO-IDE/`, начата 2026-09-22)

Параллельно HAL-проекту заведена ветка на Arduino IDE со ставленым ядром `stm32duino` (плата WeAct
Mini STM32H723VGT6), в папке `STM32-ARDUINO-IDE/sketch_sep22a`. Использует те же пины SPI2/PC0-PC3
из таблицы §2.3.

**Первая попытка** — сторонняя библиотека `Adafruit_HX8357` (`tft.begin(HX8357B)`). Ошибочный выбор:
`Adafruit_HX8357` — драйвер чипа **HX8357**, а не ILI9486, который реально стоит в этой панели.
Результат — ровный серый экран.

**Текущая версия** — порт проверенного протокола вместо сторонней библиотеки:
- `LCD_Driver.h`/`.cpp` — копия официального `Arduino/LCD_Show/LCD_Driver.cpp` без изменений (тот же
  побайтовый протокол ILI9486, что и в HAL-версии, §5)
- `Debug.h` — копия без изменений (пустой DEBUG-макрос)
- `DEV_Config.h`/`.cpp` — единственный адаптированный слой: `SPIClass SPI_2(TFT_MOSI, TFT_MISO,
  TFT_SCK)` на пинах PB_13/14/15 вместо AVR-глобального `SPI`; `LCD_CS/DC/RST/BL` = `PC_0..PC_3`;
  подсветка включается жёстким `digitalWrite(HIGH)` вместо `analogWrite()` — PC3 в плане проекта
  заведён как обычный GPIO_Output, PWM-способность не подтверждена
- `sketch_sep22a.ino` — `System_Init()` + `LCD_Init(SCAN_DIR_DFT, 200)` в `setup()`, циклическая
  `LCD_Clear()` красный/зелёный/синий в `loop()`

**Результат:** ровный серый экран, без цвета — статус, разбор и следствия для приоритета дальнейших
шагов см. `PRIZMA-DOSTOVERNOSTI.md` §7.
